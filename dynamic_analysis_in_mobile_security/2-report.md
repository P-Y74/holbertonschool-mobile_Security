# Dynamic Analysis & Cryptographic Extraction Report - Task 2

## Executive Summary
This report documents the reverse engineering and cryptographic analysis conducted on `Apk_task2`. Due to environment constraints preventing live emulator deployment, static reverse engineering via JADX was combined with offline Python simulation to bypass an intentional runtime anti-analysis lock and decrypt the application payload to recover the flag.

## Target Details
- **APK Name:** app-release-task2.apk
- **Tools Used:** JADX, Python 3 (`ctypes`, `base64`)
- **Target File:** `com/holberton/task3/MainActivityKt.java`

## Technical Methodology & Findings

### 1. Static Code Analysis
Inspection of `MainActivityKt.java` revealed the `performslowDecryption` method:
- The method retrieves a Base64 encoded payload: `cVZaW1dDQllZTFdRW1xeUlBbX21CWFtHalRZXUJFRFhNX1ZcbllGQ15cUUNSRFpcVks=`.
- The payload is passed to `xorDecrypt` along with a key generated by `slowRecursive(150)`.

### 2. Anti-Analysis Mechanism & Optimization
The `slowRecursive` method implements a naive recursive Fibonacci calculation $O(2^n)$:
```java
public static final long slowRecursive(int i) {
    return i <= 1 ? i : slowRecursive(i - 1) + slowRecursive(i - 2);
}

```

Executing $F(150)$ recursively at runtime creates an intentional denial-of-service / freeze in dynamic instrumentation environments.

To overcome this, an offline Python script computed $F(150)$ in $O(N)$ time using Java's 64-bit signed integer (`ctypes.c_int64`) overflow rules, producing the exact decimal string key required by the application.

### 3. Decryption Logic

1. Base64-decoded the raw ciphertext string to a byte array.
2. Iterated through each byte, performing an XOR operation with the corresponding character of the 64-bit signed representation of $F(150)$ (`key.charAt(i % key.length())`).
3. Reconstructed the plaintext ASCII output.

## Identified Vulnerabilities

1. **Insecure Obfuscation & Denial-of-Service Locks:** Relying on computationally intensive recursive algorithms for key generation fails against static analysis.
2. **Hardcoded Base64 Ciphertext:** Sensitive payloads hardcoded directly in APK binaries can be easily extracted and analyzed offline.

## Remediation Recommendations

* Store sensitive operational parameters securely using the Android Keystore System or retrieve them dynamically over TLS.
* Avoid relying on client-side hardcoded secrets or static XOR schemes for protection.
